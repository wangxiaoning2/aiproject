# SSE 流式输出笔记

## 为什么不能让浏览器直接调模型

API Key 只要出现在前端代码里，任何人打开 DevTools 就能拿走。所以必须是浏览器调我自己的服务端，服务端再去调模型服务商。中间这一层顺便干了三件事：藏密钥、裁剪上下文、把 token 成本算出来。

## 一帧到底长什么样

SSE 就是一段纯文本，挂在不关闭的 HTTP 连接上持续推过来。规则只有三条：一行 `event:` 声明事件名，一到多行 `data:` 承载数据，一个空行表示这一帧结束。所谓"AI 打字机"，本质上就是一堆小 JSON 拼起来的。

为什么不用 EventSource？因为它只支持 GET，没法带 JSON body 和自定义请求头，所以真实项目里基本都是 fetch 加 ReadableStream 手动解析。

## 最容易翻车的坑：chunk 不等于一帧

TCP 只是字节流，服务端一次写入的内容可能被拆成两个 chunk 送过来。如果假设 read() 拿到的就是完整的一帧，就会在某些请求里随机丢字，而且只在网络抖动时出现，极难复现。

正确做法：自己维护一个 buffer，累积解码后的字符串，按空行切分，剩下的留在 buffer 里等下一轮。中文一个字占三个字节，正好被切在两半的时候，解码必须带 stream 参数，否则会解出乱码。

## 用户点了停止，钱什么时候停

很多人以为前端不渲染就算停止生成了。不是的。前端停止读流的时候，服务端和模型之间的请求还在跑，token 还在烧，账单照记。必须把这件事传到上游去：前端调 AbortController，服务端监听连接关闭事件，收到就立刻掐掉上游的 fetch。
